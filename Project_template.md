# Project_template: RAG-бот по базе знаний QuantumForge

## Задание 1. Исследование моделей и инфраструктуры

Отчёт в [research.md](research.md). Коротко:

- YandexGPT отпал сразу: компания в ЕС, данные не должны уходить в российскую юрисдикцию.
- LLM подключаю через OpenAI-совместимый API, модель задаётся в `.env`. Для пилота облачная Claude Haiku 5.5, для продакшна
  гибрид: облако для обычных документов и локальная 7-8B модель в vLLM внутри VPC для конфиденциальных (NDA-спецификации
  клиентов, SOC 2, HR).
- Эмбеддинги локальные, `intfloat/multilingual-e5-small`: база и вопросы на разных языках, а конфиденциальные документы
  нельзя отправлять в облачный эмбеддер.
- Векторная БД FAISS: пилот маленький, нужен быстрый поиск без отдельного сервиса. Когда понадобятся фильтры по ролям
  и классу конфиденциальности, переезд на Qdrant.
- Сервер для пилота 4 vCPU / 16 ГБ без GPU. Для продакшна гибрид: CPU-нода 8 vCPU / 32 ГБ и GPU-нода с L4 24 ГБ.

## Задание 2. Подготовка базы знаний

Взял вселенную Star Wars, источник [Wookieepedia](https://starwars.fandom.com/) (тексты под CC BY-SA). Список из 35 статей
в `kb/pages.txt`: 14 персонажей, 8 планет, 5 технологий и объектов, 5 организаций и понятий, 3 битвы.

Как собирал:

- `kb/fetch.py` скачивает статьи через MediaWiki API фандома (`action=parse`), выкидывает инфобоксы, сноски, цитаты,
  разделы «Behind the scenes», «Appearances», «Sources» и обрезает статью примерно до 1 100 слов. Исходники лежат в `kb/raw/`.
- В `terms_map.json` 331 замена (исходное → вымышленное). Заменял не только героев, но и планеты, расы, организации,
  оружие, корабли, летоисчисление (BBY/ABY → BVC/AVC), узнаваемые понятия вроде Order 66, clone troopers, carbonite,
  podracer, sabacc и второстепенных персонажей, по которым мир легко узнать. Примеры: Darth Vader → Xarn Velgor,
  Death Star → Void Core, the Force → the Flux, Jedi → Aethari, Sith → Morrak, lightsaber → lumeblade, Tatooine → Drysa,
  Millennium Falcon → Crimson Kestrel.
- `kb/replace_terms.py` заменяет всё одним проходом регулярным выражением по всем ключам. Длинные ключи идут раньше
  коротких, поэтому «Darth Vader» не превращается в «Xarn Velgor» по частям, а уже заменённый текст повторно не
  трогается. В конце скрипт проверяет, что ни одного ключа словаря в базе не осталось. Имя файла строится из нового
  заголовка.
- Кандидатов в словарь собирал по частоте имён собственных в скачанных текстах. После замены прогонял тот же подсчёт
  по результату и добавлял то, что ещё узнаётся.

Результат: `knowledge_base/` из 35 документов в Markdown (одна сущность, один файл), около 41 тысячи слов. Тексты
остались связными: Kaelen Vossar, Aethari Knight родом с пустынной планеты Drysa, стал Xarn Velgor, Dark Lord of the
Morrak. Проверил, что модель не знает этот мир по памяти: на вопросы без контекста «Who is Kaelen Vossar?»,
«Кто такой Xarn Velgor?», «What is the Void Core built by the Dominion of Astra?» Claude Haiku 5.5 отвечает «не знаю».

Как пересобрать: `python kb/fetch.py && python kb/replace_terms.py`.

## Задание 3. Создание векторного индекса базы знаний

Код: `rag/indexing.py` (чанки, эмбеддинги, работа с FAISS) и `build_index.py` (полная сборка). Подробности и пример
запроса в [index/README.md](index/README.md).

- Модель: [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small), 384 измерения.
  Выбрал многоязычную, потому что база на английском, а спрашивать будут и по-русски.
- База: 35 документов из `knowledge_base/`.
- Чанков: 235, в среднем 175 слов (1 600 символов, перекрытие 15%). У каждого чанка сохранены файл, заголовок
  документа, раздел, номер и позиция в документе, чтобы бот мог сослаться на источник.
- Индекс: FAISS, косинусная близость через нормализацию и `IndexFlatIP`, в обёртке `IndexIDMap2`.
- Время генерации: 8 секунд вместе с загрузкой модели.

Пример: на вопрос «Who trained Kaelen Vossar as a Novitiate?» первыми приходят два чанка из `kaelen_vossar.md` и
один из `tavin_vossar.md` со score 0.84-0.87. На вопросы не по базе (Kafka, Netflix, VPN, пароль root, чемпионат мира)
лучший score не выше 0.76. По этим замерам потом выбран порог «не знаю» 0.78.

## Задание 4. Реализация RAG-бота с техниками промптинга

Модуль `rag/`:

- `indexing.py` загружает индекс и ищет (из задания 3). Запрос кодируется той же моделью e5, что и документы, с
  префиксом `query: `.
- `pipeline.py` собирает саму цепочку. Нормализую пробелы в запросе, ищу топ-5 чанков, отбрасываю всё ниже порога 0.78,
  собираю промпт, отправляю в LLM, разбираю ответ на шаги и итог, номера цитат `[n]` превращаю в имена файлов-источников.
  Если после порога не осталось ни одного чанка, LLM вообще не вызывается и бот отвечает «Я не знаю»: иначе модель
  начинает отвечать по памяти.
- В `prompts.py` system-промпт, примеры few-shot и шаблоны ответов.

Готовую цепочку `RetrievalQA` из LangChain не брал: она прячет промпт и разбор ответа, а мне нужно было управлять
порогом, форматом шагов, ссылками на фрагменты и потом встраивать защиту из задания 5. Из LangChain взят только
сплиттер.

Промпт собран так: system (роль, правила, формат), потом два примера few-shot парами user/assistant, потом контекст и
вопрос. Чанки в контексте пронумерованы, с именем файла и заголовком, текст в маркерах `<<< >>>`.

Few-shot: два коротких примера из самой базы (`grovath.md` и `ardel_strosk.md`), один вопрос на русском, один на
английском, чтобы модель видела, что отвечать надо на языке вопроса. Оба в том же формате, что я жду от модели, и
специально не совпадают с вопросами из демонстрации и золотого набора, чтобы успех на тестах нельзя было объяснить
примером.

Chain-of-Thought: в system-промпте «сначала рассуждай, потом отвечай, пиши шаги», формат «Шаги: 1… 2… Ответ: …».
В Telegram шаги показываются свёрнутой цитатой под ответом, в консоли по флагу `--steps`.

LLM подключается через OpenAI-совместимый API (`openai` SDK; `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` в `.env`, пример
в `.env.example`). Для пилота взял Claude Haiku 5.5 через совместимый эндпоинт Anthropic, как и рекомендовал в
задании 1. Наблюдение: Claude Sonnet 5.5 на этот промпт отдаёт пустой ответ с `finish_reason: content_filter`, его
классификатор принимает просьбу «пиши шаги рассуждения» за попытку вытащить внутреннее рассуждение модели. Haiku 5.5
и Opus 5.5 работают нормально. Поэтому пустой ответ и отказ модели обрабатываются отдельно: пользователь получает
«Модель отказалась отвечать», а не пустое сообщение.

Интерфейсы:

- `python cli.py [--steps]`, консольный REPL;
- `telegram_bot.py`, Telegram-бот (username @QuantumForgeKBot, отображаемое имя qforge_kb_bot). Long polling Bot API
  на `httpx`, ответ в HTML, источники моноширинным шрифтом, шаги в свёрнутой цитате;
- `Dockerfile` и `docker-compose.yml`: сервис `bot` (бот и FAISS в одном процессе, индекс и база монтируются томами)
  и `indexer` для пересборки индекса. Модель эмбеддингов скачивается при сборке образа, torch ставится CPU-версии.

Диалоги (5 успешных и 2 «Я не знаю») с шагами рассуждения в [docs/task4_dialogs.md](docs/task4_dialogs.md). Два
случая «не знаю» показывают оба механизма. На «Who is Darth Vader?» поиск находит чанки про Kaelen Vossar (score 0.80),
но модель честно говорит, что имени Darth Vader в контексте нет. На вопрос про Kafka поиск ничего не вернул выше порога,
и до LLM запрос не дошёл.
